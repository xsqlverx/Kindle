## Implemented

- `app/src/main/assets/academic/catalog.json` is generated by `scripts/build_academic_pack.py`
  from manually curated source content. Seven original PDFs (3,121,843 bytes) are bundled
  unchanged. The JSON records original filenames, full SHA-256, page counts and page links.
  No generated lessons, answer bank, syllabus credentials or synthetic user progress.
- Six courses, twenty theory modules and 140 source-linked groups: 66 THEORY, 18 CODE,
  15 LAB, 36 ACTIVITY (35 source activity rows plus mandatory portfolio/journal audit),
  three INTERNAL groups, one FOUNDATION and one OPTIONAL excluded-from-ESE group.
  Group counts measure catalog entries, not official exam questions or completed learning.
- `AcademicStore` installs 122 ExamTopic records (confidence 0, revision unreported) and
  18 Python CodingAttempt records (no app outcome/lesson, createdAt 0) using stable `aisat26:` IDs
  and Room INSERT IGNORE inside a transaction. Retry/forced import preserves edits, notes,
  outcomes, revision dates and IDs. No schema change (Room remains v4), destructive migration,
  attendance/timetable alias merge, default exam overwrite or mock seeding.
- Separate committed preferences persist the suggested roadmap, daily budget, selected
  modules, explicit coverage and target completion. Fresh installs initially suggest 50
  min/day; this is an editable assistant choice. Initialization uses its own mutex, so the
  asset import does not stall unrelated session controls. Wipe coordinates with initialization;
  its marker prevents reimport/regeneration on reopening, including a wipe before first import.
  The read-only source catalog remains; explicit Work on this restores just that source item.
- `SyllabusPlanner` creates date-only first-pass targets in syllabus order, rotating courses,
  then recall passes through Dec 6 (the day before the first listed final). It never uses contact
  hours as personal effort. Budget 10–180 is divided into at most four blocks; all-theory is
  the explicit default because teacher portions are missing. One weekly portfolio audit stays
  separate. Lab/CAD/other activity items can be deliberately chosen from the library. No guessed
  lab selection, relative activity-week conversion, subject exam assignment or daily clock time.
- Exam Prep shows an editable study map, source library by course with search, original-page
  links, self-rated confidence/revision, study label/material editing, explicit coverage and
  coding outcome access. Roadmap has completion/undo, overdue entries, capacity before the
  next window and refresh from today; refresh keeps completed targets and real blocks/sessions.
  The calendar shows relevant student milestones on S1/S2 pages with optional past dates.
- Today/Plan/College expose today's dated calendar milestone when present, otherwise the
  next S1 exam window; these are college reference dates. Today receives at most two due
  roadmap suggestions. Saved urgent tasks, chosen priorities, urgent deadlines and explicit revision/
  retry queues rank before these broad suggestions. The full imported catalog does not flood
  automatic choices. Manual study-source selection still reaches every imported item.
- Work on this/Choose its study window carries the actual source ID and edited material into
  the existing exact-minute composer, real collision/session safeguards, focus/capsule, resume
  note and Review. Existing session completion never implies mastery, coverage or submission.
  Target completion and coverage are explicit separate user actions.
  Library/coding selection reuses the latest actual resume note/material when present;
  syllabus descriptions never masquerade as a student's recorded lesson.
- Original-page viewer uses Android PdfRenderer on IO with bounded one-page bitmaps, closed
  descriptors, temporary cache cleanup, page controls, pinch/pan and an accessible zoom/reset
  button. No network, viewer dependency, storage permission or signing/build configuration change.
